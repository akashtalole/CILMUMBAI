# SPEC-007: Query API, access tiers and citation check

## 1. Problem and outcome

Every surface (web, WhatsApp, agents, public API) must read through one layer that applies access tiers and checks citations. Otherwise one forgotten path leaks data or lets an uncited claim through.

When done, a single HTTP API serves places, named views and answers. Every request runs under a tier. Every answer that contains text composed by a model passes a citation check in code before it is returned.

## 2. User stories

- As a resident, I want an answer whose numbers I can trust and check.
- As the citizen desk, I want tools that return facts with ids I can cite.
- As the platform, I want no path that bypasses tiers.

## 3. Requirements

| Id | Requirement |
|---|---|
| R1 | The API shall expose `GET /places`, `GET /point`, `GET /views/{name}`, `GET /facts/{id}`, `GET /sources/{sha256}/pages/{n}` and `POST /answers/check`. |
| R2 | Every request shall resolve to exactly one tier: public, contributor, researcher, official or reviewer. |
| R3 | If a request carries no valid credential, then the API shall serve it as public. |
| R4 | The API shall filter every result by the caller's tier using tier labels on facts, before results leave the query layer. |
| R5 | `POST /answers/check` shall extract every amount, date, tender or bid identifier, survey number and proper name from an answer and confirm each appears in a fact the answer cites. |
| R6 | When the citation check fails, the API shall return the unmatched items and shall not mark the answer as checked. |
| R7 | Every fact returned shall include source sha256, page, quote, tier, `quote_check` and the date the source was fetched. |
| R8 | The API shall log each request with tier, endpoint, parameters and returned fact ids, and no personal data. |
| R9 | The API shall rate-limit public callers per address. |

## 4. Acceptance criteria

| Id | Given | When | Then | Verifies |
|---|---|---|---|---|
| AC1 | The running API | Each R1 endpoint is called with valid input | Each returns 200 with its documented shape | R1 |
| AC2 | No credential | A view is called | The response header shows tier `public` | R2, R3 |
| AC3 | A fact labelled researcher-only | A public caller requests a view that would include it | The fact is absent; a researcher caller sees it | R4 |
| AC4 | An answer "Contract value ₹4.2 crore, due 31 May 2026 [f1]" where f1 holds those values | It is checked | It passes | R5 |
| AC5 | The same answer with "₹5 crore" | It is checked | It fails, listing "₹5 crore" as unmatched | R5, R6 |
| AC6 | An answer in Marathi with amounts in Devanagari numerals | It is checked against facts in Latin numerals | Equal amounts match | R5 |
| AC7 | Any returned fact | Its fields are inspected | All R7 fields are present | R7 |
| AC8 | A request | It is logged | The log has tier, endpoint and fact ids and no phone, name or message text | R8 |
| AC9 | A public client sending more than the limit | Requests continue | Further requests get 429 | R9 |

## 5. Interfaces and data contracts

OpenAPI document generated by the framework, committed, and checked in CI.

```
POST /answers/check
{ "text": "...", "cited_fact_ids": ["f1","f2"], "language": "mr" }
→ { "ok": false, "unmatched": [{"kind": "amount", "text": "₹5 crore"}], "matched": [...] }
```

Amount normalisation: lakh and crore, Devanagari and Latin numerals, "Rs", "₹" and "रु." are equivalent. Dates in any common Indian format.

## 6. Non-functional requirements

- p95 under 400 ms for views on the demo ward.
- Citation check under 100 ms for a 300-word answer.

## 7. Constitution

| Article | How this spec upholds it |
|---|---|
| C3 | R5, R6: citation check in code |
| C7 | R8: no personal data in logs |
| C8 | R2 to R4: single tier per request, filtered in the query layer |

## 8. Out of scope

Sign-in flows (Cognito wiring in SPEC-013; until then, tiers come from signed development tokens). Search endpoints (SPEC-017).

## 9. Design notes

- FastAPI; one dependency resolves the tier; the repository layer takes the tier as a required argument so it cannot be forgotten.
- Proper-name extraction for the check: match against names of nodes in cited facts and the glossary; a capitalised phrase or Devanagari name not found there is reported as unmatched.
